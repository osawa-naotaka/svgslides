# プロジェクト憲章 - SVGSlides

## 1. プロジェクト概要

### 1.1 プロジェクト名
- **SVGSlides**  
SVG編集・プレゼンテーションソフト

### 1.2 プロジェクト実行の背景
- プレゼンテーション資料の作成は時間がかかり、デザインの一貫性を保つことが難しい
- LLMを活用してSVG形式のスライドを生成できるようになったが、既存のツールでは複数のSVGファイルを効率的に管理・編集・表示する機能が不足している
- PowerPointやKeynoteはGUIベースの編集が中心で、LLM生成コンテンツとの連携やテキストベースの微調整に不向き
- プログラマブルな方法でプレゼンテーション資料を管理したいニーズがある

### 1.3 プロジェクトの目的
- LLMで生成したSVGスライドを効率的に管理・編集・表示できるデスクトップアプリケーションを開発する
- SVGテキストの直接編集とリアルタイムプレビューにより、迅速な調整作業を可能にする
- シンプルなYAML形式でのドキュメント管理により、バージョン管理との親和性を高める

### 1.4 提供価値
- **時間削減**: LLM生成SVGの活用により、プレゼン資料作成時間を大幅に短縮
- **柔軟な編集**: SVGコードを直接編集できることで、細かい調整が即座に可能
- **即時フィードバック**: 編集結果がリアルタイムにサムネイルで確認でき、試行錯誤が容易
- **シンプルな管理**: YAML形式による軽量なドキュメント管理で、Git等のバージョン管理システムとの統合が容易
- **プレゼン実行**: フルスクリーン表示とキーボード/マウス操作による快適なプレゼンテーション体験

## 2. メンバーと利害関係者

### 2.1 メンバー
- **lulliecat**: PM・仕様作成・実装・検証

### 2.2 利害関係者
- **プレゼン実行者（プライマリユーザー）**
  - プレゼン資料作成経験はある
  - 作成の手間をLLMで減らしたい
  - コードやテキストベースの編集に抵抗がない
  - 効率的なワークフローを求めている

## 3. プロジェクトスコープ

### 3.1 スコープ内の項目
- 複数SVGファイルを一括で管理
- 複数SVGファイルをプレゼン形式で表示
  - フルスクリーン表示
  - キーボード（カーソルキー）とマウス（スクロール）での操作
- SVGファイルを編集してその結果を即時画像で確認
  - 左カラム：サムネイルリスト表示
  - 右カラム：SVGテキストエディタ
  - リサイズ可能な2ペインレイアウト
- YAML形式でのドキュメント管理（SVGファイル参照と順序）
- 新規ドキュメント作成機能
- LLM生成SVGファイルのインポート機能

### 3.2 スコープ外の項目
- GUIを使った画像の編集（ドラッグ&ドロップでの図形配置など）
- LLMとの直接的な統合（API連携など）※外部でSVGを生成してもらう前提
- アニメーション機能
- 複数ユーザーでのリアルタイムコラボレーション
- クラウド同期機能
- PDF/PowerPointなど他形式へのエクスポート（初期バージョンでは対象外）
- 音声・動画の埋め込み

### 3.3 予算
なし（個人開発プロジェクト）

### 3.4 リスク
- **技術的リスク**
  - Electronのバンドルサイズが大きくなる可能性 → 配布方法を検討
  - 大量のSVGファイル読み込み時のパフォーマンス低下 → 遅延読み込み等の最適化が必要
  - SVG編集時のリアルタイムレンダリングのパフォーマンス → デバウンス処理の実装
  
- **ユーザビリティリスク**
  - SVGコードの直接編集がユーザーにとってハードルとなる可能性 → 明確なドキュメントとサンプル提供
  - エラーハンドリング不足による不正なSVGの表示問題 → バリデーション機能の実装
  
- **スコープクリープリスク**
  - 機能追加要望により開発が長期化する可能性 → MVP（Minimum Viable Product）を明確に定義し、段階的リリースを計画
  
- **保守性リスク**
  - 一人での開発のため、コードの属人化 → コメント・ドキュメントの充実、テストコードの作成
